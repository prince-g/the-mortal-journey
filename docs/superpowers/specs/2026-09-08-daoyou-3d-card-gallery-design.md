# 道友 3D 闪卡画廊设计

日期：2026-09-08  
状态：已确认设计，等待实现计划

## 背景

首页 `WallpaperGallerySection` 顶部已有“仙途 / 惊鸿 / 道友”三张绿色入口卡片。当前卡片之间的桌面间距偏小，并且三张卡片都是不可导航的 `figure`。本次要扩大入口卡片间距，并让“道友”进入一个由 RuiC Card 流程生成的独立 Three.js 闪卡网页。

道友页面展示九张卡片，桌面固定为 3×3。九张卡片暂时共用用户提供的韩立竖版图片，同时具备随视角变化的流光、人物与背景景深、倾斜和翻面交互。“仙途 / 惊鸿”只建立可扩展的入口配置，不创建空白内容页。

## 目标

- 桌面端明显扩大三张绿色入口卡片之间的横向间距，移动端继续保持可用的横向滚动。
- 点击“道友”时在当前标签页打开 `/gallery/daoyou/`。
- 使用真实 Blender 卡片几何及 Three.js 材质，不用平面截图冒充 3D 模型。
- 用一个 WebGL 场景展示九张共享韩立素材的卡片，桌面排列为 3×3。
- 从韩立原图派生人物、背景和线稿层，在静止正面尽量还原原图，在视角变化时形成层次景深。
- 保留配置入口，使“仙途 / 惊鸿”以后只需补充目标地址和对应页面即可接入。
- 在桌面和 390px 手机宽度下保持可访问、可操作且无横向溢出。

## 非目标

- 本次不制作“仙途 / 惊鸿”的内容页，也不让它们跳转到占位页面。
- 不为九张卡片生成九套不同画面或文案。
- 不向韩立卡面擅自添加姓名、招式、版本号或官方联名等文字。
- 不发布网站，不改动现有视频画廊、壁纸滚轮和启动加载器的业务逻辑。

## 方案选择

采用独立静态 Three.js 页面，而不是把完整的 RuiC 着色器和 Blender 导出逻辑重写进 React。

生成源项目位于 `card-projects/daoyou/`，保存配置、分层素材、可编辑的 `card.blend` 和流水线输出；项目本地 Blender 工具目录不提交。可部署网页复制到 `public/gallery/daoyou/`，因此 Vite 会把它原样纳入构建产物。首页使用普通同页导航链接进入该页面，避免 iframe 的焦点、尺寸和手势问题，也不需要在主 React 包中新增 Three.js 运行时代码。

## 首页入口设计

将字符串数组改为集中式入口配置：

```ts
type GalleryEntry = {
  id: "xiantu" | "jinghong" | "daoyou";
  label: string;
  href?: string;
};
```

“道友”配置 `href: "/gallery/daoyou/"`，渲染为可聚焦的链接；“仙途 / 惊鸿”暂不提供 `href`，保持现有展示行为。后续增加内容时，只需在配置中补充地址，不需要改动卡片结构或动画逻辑。

桌面变量 `--gallery-card-gap` 调整到约 32–40px 的响应式范围；手机断点继续使用约 0.8rem 的滚动间距，避免减少单卡可视宽度。可点击卡片提供明确的指针光标和键盘焦点样式，但不改变现有绿色视觉语言。

## 分层素材设计

用户提供的 768×1344 韩立图片作为身份与构图基准，原文件不覆盖，复制后保存为源图。派生四个同尺寸或统一放大到共享画布尺寸的卡面层：

1. `background.png`：补全人物身后的山峦、云雾和道路，保持冷蓝灰色调。
2. `subject.png`：从原图提取韩立人物及必要的衣摆、发丝透明边缘，保持原姿态和面容。
3. `lineart.png`：与人物层严格配准的稀疏轮廓线，只用于视角高光，不重绘新姿态。
4. `text.png`：透明空层，满足统一材质接口，但不添加用户未要求的文字。

原图另存为 `source.jpg` 用于对照和溯源。生成后先数值检查 alpha，再进行透明边缘和图层配准的视觉检查。正视状态以人物层覆盖背景补全区域，使主体身份和构图尽量贴近原图；视角偏移受到安全范围限制，避免露出明显的补图区边缘。

## Blender 与 Three.js 产物

使用 RuiC Card 流水线创建有厚度和圆角的真实卡片几何，保留 `web_front`、`web_edge`、`web_back`、`web_gold` 材质命名约定。可编辑 Blender 场景保存在生成源项目中，网页加载从该场景导出的几何。

网页使用一个 renderer、一个 scene 和一套共享纹理。基础卡片加载完成后克隆为九个卡片根节点，避免创建九个 WebGL 上下文和重复下载纹理。桌面把九个根节点按三列三行定位；射线检测确定当前悬停或拖动的卡片，每张卡片维护独立的目标旋转和翻面状态。未交互卡片只进行极弱的视角响应，悬停卡片获得更明显的倾斜、箔面光谱和人物视差。

着色器沿用 RuiC Card 的有界视线方向 UV 偏移、角度相关光谱相位、稀疏线稿高光和卡边独立材质。人物发光保持克制，避免用高亮掩盖分层质量。纹理、几何和材质共享，卡片变换及交互状态独立。

## 页面与交互

页面采用深色冷调背景，与韩立画面和现有站点氛围衔接。顶部只保留页面标题和“返回首页”链接，主区域用于九卡画廊，不移植技能模板中与本需求无关的下载、材质切换或参数面板。

- 鼠标移动：改变当前视角和箔面光谱。
- 悬停：当前卡片轻微抬升和倾斜，人物与背景产生有界视差。
- 拖动：旋转当前卡片；越过翻面阈值后展示卡背。
- 键盘：卡片可聚焦，`Enter` 或空格切换正反面，方向键提供小幅旋转反馈。
- 触屏：单指拖动当前卡片；页面纵向滚动仍可用，不劫持非卡片区域手势。
- 减少动态效果：关闭持续漂移和插值动画，保留即时、低幅度的状态切换。

## 响应式布局

- 宽屏和普通桌面：严格三列，九张卡片呈 3×3。
- 中等宽度：两列，以保证卡片仍能辨认和操作。
- 390px 手机：单列，卡片宽度受视口和安全边距约束，页面纵向滚动，无横向溢出。

Three.js 相机会在断点变化时重新计算卡片位置和画布高度，而不是仅用 CSS 缩放一个固定尺寸画布。设备像素比设置上限，兼顾高分屏清晰度和九卡渲染性能。

## 加载与失败处理

页面先显示轻量加载状态，几何和四层纹理全部可用后再显示画廊。任何关键资源失败时展示可读的错误信息、重试按钮和返回首页链接，不留下空白画布。WebGL 不可用时使用原韩立图片生成的静态卡面网格作为降级内容，仍保持九张卡和响应式排版。

## 可访问性

- “道友”入口使用真实链接，支持键盘和浏览器原生导航语义。
- 3D 卡片提供可聚焦的等价交互层、中文可访问名称和翻面状态。
- 焦点样式在深色背景上满足清晰可见要求。
- 状态提示不只依赖颜色；加载错误和翻面状态可被辅助技术读取。
- 装饰性流光不进入可访问名称，减少动态效果设置受到尊重。

## 验证标准

1. 运行项目现有完整测试命令；若仓库没有统一脚本，则运行所有 `tests/*.test.mjs`，并把既有失败与本次回归分开报告。
2. 运行 RuiC 资产校验，确认透明通道、画布尺寸和图层配准。
3. 运行 RuiC 流水线，确认生成 `card.blend`、真实导出几何和网页资源。
4. 在桌面浏览器确认首页卡片间距、道友导航、九卡数量和 3×3 排列。
5. 实测鼠标视角流光、悬停景深、拖动、双向翻转及键盘操作。
6. 在 390×844 下确认单列布局、触摸手势、内部滚动和无横向溢出。
7. 检查 WebGL 着色器、网络资源和浏览器控制台无新增错误或警告。
8. 运行 `npm run build` 和 `git diff --check`。

## 完成判定

只有当首页入口、九卡网页、A 方案分层、真实 3D 几何、交互、响应式降级和上述验证全部完成，才视为本功能完成。静态截图或仅能加载的 ready 标记不能代替实际浏览器交互验证。
